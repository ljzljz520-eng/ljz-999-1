# 汽配条码追踪接口站

柜台扫配件条码后，立即展示 **批次、适配车型、货架位置、供应商、召回状态**；
离线时按有效期使用本机缓存；连续出现问题的批次会被自动挂起，柜台再扫码直接红色风险拦截。

## 启动（零依赖，Node.js ≥ 18）

```bash
node server.js
# 柜台扫码页  http://localhost:3000/
# 后台管理页  http://localhost:3000/admin
PORT=8080 CACHE_TTL_MS=60000 node server.js   # 自定义端口 / 缓存有效期
```

首次启动自动生成 `data/db.json` 种子数据（5 个批次、6 个条码，其中
`BP-0003-01` 火花塞已标记召回，方便演示）。

## 种子条码

| 条码 | 配件 | 说明 |
|---|---|---|
| BP-0001-01 / 02 | 机油滤清器 | 正常 |
| BP-0002-01 | 前刹车片 | 正常，可连续上报 3 次问题演示自动挂起 |
| **BP-0003-01** | 铱金火花塞 | **已召回，扫码即红色拦截** |
| BP-0004-01 | 空气滤清器 | 正常 |
| BP-0005-01 | 正时皮带套装 | 正常 |

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/scan/:code` | 扫码查询，返回配件+批次+风险判定；响应头 `X-Cache-TTL` 下发缓存有效期 |
| POST | `/api/issues` | 柜台上报问题 `{code,type,note}`；批次连续问题达 3 次自动挂起 |
| GET | `/api/admin/overview` | 后台总览（配件/批次/流水） |
| POST | `/api/admin/batches/suspend` | 人工挂起批次 `{batchId,reason}` |
| POST | `/api/admin/batches/resume` | 恢复批次（连续计数清零，累计保留） |
| POST | `/api/admin/recall` | 标记/解除召回 `{code,recalled,reason}` |

## 风险判定（服务端统一下发）

- `danger` 拦截：配件被召回 **或** 所属批次被挂起（人工 / 自动）
- `warning` 预警：批次存在连续问题（未达挂起阈值）
- `ok`：正常

## 离线缓存策略（Service Worker `/sw.js`）

1. 扫码结果按响应头 `X-Cache-TTL`（默认 5 分钟）缓存，**有效期内秒开**，同时后台静默刷新；
2. 缓存过期后联网正常取新数据；若此时离线，则用过期缓存兜底，页面顶部**强提示
   "离线缓存已过期，风险状态可能已变化"**，且风险横幅标注结果来自离线快照；
3. 从未缓存过的条码在离线时直接拒绝放行（风险优先，不允许出库）；
4. 离线期间的问题上报存入本机 outbox，恢复联网后自动补传（每 15 秒 + 手动按钮）；
5. 页面提供"离线演示模式"开关，无需断网即可验证上述全部流程。

> Service Worker 需在 `localhost` 或 HTTPS 下生效。生产部署请置于 HTTPS 反向代理之后。

## 验证流程建议

1. 扫 `BP-0003-01` → 红色召回拦截；
2. 扫 `BP-0002-01` → 正常；勾选"离线演示模式"再扫 → 显示有效缓存；
3. 等缓存过期（或把 `CACHE_TTL_MS` 调小重启）后离线扫 → 过期缓存警告；
4. 取消离线，对 `BP-0002-01` 连续上报 3 次"质量缺陷" → 第 3 次自动挂起；
5. 再扫该条码 → 直接红色拦截，提示批次已挂起；后台 `/admin` 可查看流水并恢复。
